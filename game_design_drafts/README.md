# Game design drafts: start here

Working drafts for **Junior Astronaut Mission Trainer** (NASA Space Apps 2026, challenge *Build a Junior Astronaut Mission Trainer*, ages **7–12**). Nothing here is final. It's here so you can jump in on mechanics.

## Read in this order (about 15 minutes)

1. **`01_core_loop.md`**: the one decision the demo is built around. **This is what we're building first.**
2. **`02_mechanics_and_history.md`**: the mechanic ideas, each tied to a real mission, split into "in the demo" and "next version".
3. **`03_real_numbers.md`**: the real NASA values we can use, each with its source.
4. **`04_rules_and_open_questions.md`**: design rules we committed to, and **the questions we need help with**.
5. **`05_assets.md`**: the graphics we picked (human-made, free to use).

Background, if you want more: `../CHALLENGE.md` (official challenge text), `../JUDGING.md` (how judges score), and `../eda/riesgos_a_mecanicas.md` (the long design doc, in Spanish).

## The idea in three sentences

On Mars, a message to Earth takes 3–22 minutes **each way**, so the crew has to decide alone. Two kids each play a role that sees something the other can't, and they must agree how to spend **one work slot** before a solar storm. Every choice saves something and costs something, and they can replay to compare.

## How to contribute

- Write your ideas in a new file here (e.g. `idea_<your-name>_<topic>.md`), or comment on the open questions in `04`.
- For any mechanic, say: **what the kid decides · what it costs · what it teaches · which real mission or NASA data backs it**.
- **Keep it simple.** The challenge warns that 2–3 core resources work better than 5–6 for this age group.
